# WarriorPlus Evidence Sprint SOP

2026-08-13 | Cody | Status: Active

## Purpose

Run a focused WarriorPlus research sprint that produces a defensible first product decision for ZedBiz.

## Scope

Included:

- WarriorPlus marketplace research.
- Product, seller, niche, hook, and offer evidence capture.
- Affiliate validation prep and logging.
- Scorecard-driven product selection.

Excluded until after first launch and 30-day review:

- JVZoo, ClickBank, and Whop expansion.
- Recurring automation buildout.
- Full software/product build.
- Broad brand architecture work.

## Setup Gate

Before research begins:

- Confirm Airtable base is available.
- Confirm Products, Offer Briefs, Decision Scorecard, Affiliate Validation, Release Readiness, and Claims & Rights Register tables exist.
- Confirm GitHub source-of-truth folder exists.
- Confirm Notion plan links to Rocky, Ruby, and Manus review pages.
- Confirm Asana project is available or create execution tasks manually if Asana is not callable.

## Research Sample Rule

Use a reproducible sample, not a single-day vibe check.

Capture:

- Current leaders.
- Recent launches.
- Category examples from AI, PLR/MRR, affiliate tools, and traffic.
- Similar/copycat offers for each candidate lane.
- Negative evidence and reasons buyers or affiliates may reject an offer.

Freeze the initial sample before choosing the winner.

## Product Record Minimum

Each product record should include:

- Product name.
- Product URL.
- Seller.
- Marketplace segment.
- Niche.
- Product type.
- Source date.
- Front-end price when visible.
- Main promise.
- Evidence notes.

## Offer Decision Flow

- Create an Offer Brief for each serious candidate.
- Score each candidate in Decision Scorecard.
- Add all evidence links and notes.
- Run affiliate validation on top candidates.
- Complete Release Readiness and Claims & Rights checks before build.
- Select a product only if hard stops are clear.

## 72-Hour Demo Rule

The 72-hour clock starts after a candidate passes the evidence gate and required inputs are available.

A working demo means:

- The buyer can see the promised output.
- The output is created by a repeatable process.
- The demo can be shown in under three minutes.
- The product does not require custom code, custom install, or live client setup for first proof.

Disqualify from first build if:

- New software infrastructure is required.
- Delivery depends on unverified PLR/MRR rights.
- Claims require income proof that does not exist.
- Support requires one-on-one setup for typical buyers.

## Completion Evidence

The sprint is complete when:

- Airtable has the defined research sample.
- Top candidates have offer briefs.
- Scorecards include evidence links.
- Affiliate responses are logged.
- Release readiness is complete for the proposed winner.
- Notion records the decision and next action.
- GitHub holds any templates, prompts, or scripts used.
